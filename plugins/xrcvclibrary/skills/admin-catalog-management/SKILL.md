# Manage the Administrative Catalog and Taxonomies

Use the authenticated XRCVC Library MCP tools and server-enforced role checks. Membership ID is the server's single identity source: resolve it through the existing OAuth connection and `get_authenticated_identity`; never ask the user to paste a bearer value, OAuth code, or token.

## Authorization

- Staff, Admin, and Developer may create or update catalog records and taxonomy values and may run catalog or taxonomy imports.
- Only Admin and Developer may delete catalog records or taxonomy values. Staff deletion is forbidden even if the user asks for it.
- A claimed role in conversation never overrides the effective role returned by `get_authenticated_identity`.
- A `403` is an authorization result. Do not retry through another route or tool.

## Catalog mutations

- Use `create_admin_catalog_item` for a new Book, Teaching Learning Aid, or Tactile Diagram. Use `update_admin_catalog_item` only after retrieving the selected administrative catalog detail and confirming its `resource_type` and `resource_id`.
- Use `delete_admin_catalog_item` only for Admin or Developer after showing the exact item and receiving explicit confirmation that it should be permanently deleted. Dependency checks may still reject the deletion.
- Preserve server-managed IDs and audit fields. Do not copy IDs from one resource type to another or invent fields that are absent from the tool schema.
- Use `bulk_import_admin_catalog` only with a supported import target and validated CSV content. Explain whether the import can create new rows, update existing rows, or both before execution.

## Taxonomy mutations

- Use `create_admin_taxonomy_item`, `update_admin_taxonomy_item`, and `delete_admin_taxonomy_item` only with a supported family, taxonomy type, and exact returned taxonomy ID.
- New taxonomy IDs are stable uppercase identifiers generated by the server. The lowercase `slug` is title-derived. Updating a title refreshes the slug without changing the document ID.
- Before deleting, retrieve or review the taxonomy value and state that catalog references can block deletion. Never replace a taxonomy ID with its slug or display title.
- Use `bulk_import_admin_taxonomy` only with a supported target and validated CSV content; it may create or update records.

## Mutation workflow

1. Resolve the effective role, retrieve the current record or relevant taxonomy list, and identify the exact target.
2. Validate the proposed fields against the live MCP input schema. Explain the intended change and whether it creates, overwrites, or permanently deletes data.
3. Execute only after the user has clearly authorized that exact mutation. Always request fresh confirmation immediately before permanent deletion or a bulk import that can update existing records.
4. Report the tool result precisely. When possible, retrieve the affected record afterward and distinguish successful verification from an accepted but unverified mutation.

## Safety and response rules

- Do not turn a request for instructions, a preview, or a comparison into an actual mutation.
- Do not silently broaden a single-record request into a bulk operation.
- Present audit actors as the returned full name paired with the matching Membership ID. Never expose Firebase UIDs or credentials.
- State whether the operation was created, updated, deleted, rejected by dependencies, denied by role, or not executed.
